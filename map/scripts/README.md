# map/scripts — 座標補正工具

把 `data/builtin.json` 的座標,用**政府門牌位置開放資料**補到**門牌級**(誤差約 10m 內)。

這是**建置時**工具:CSV 只留在本機 `_src/`(已 gitignore),**不進 git、不上 GitHub Pages**,
瀏覽器端完全不會載到。產物只有寫回 `builtin.json` 的座標。

---

## 資料來源(要用時再下載)

### 臺北市 ✅ 可用

- 資料集頁:<https://data.taipei/dataset/detail?id=b7c8e724-1e98-45ee-a0bd-f3840623ed97>
- 提供機關:臺北市政府民政局 ・ 授權:政府資料開放授權條款第 1 版(免費)
- 規格:**CSV 約 124 MB / 1,155,531 筆 / UTF-8 / 每月更新**
- 欄位:`省市縣市代碼, 鄉鎮市區代碼, 村里, 鄰, 街路段, 地區, 巷, 弄, 號, 橫座標, 縱座標`
- 座標系:**TWD97 TM2(EPSG:3826)**,不是經緯度 → 腳本內 `twd97ToWgs84()` 負責換算

下載(存成 `_src/taipei-address.csv`):

```bash
curl -L -o map/scripts/_src/taipei-address.csv "https://data.taipei/api/dataset/b7c8e724-1e98-45ee-a0bd-f3840623ed97/resource/ce76ca0c-7f94-4935-ab47-1d2a41ca2abb/download"
```

> ⚠ 每月更新時 `resource id` 可能會變。連結失效就到上面的資料集頁重拿,或用
> `curl -s "https://data.taipei/api/frontstage/tpeod/dataset.view?id=b7c8e724-1e98-45ee-a0bd-f3840623ed97"`
> 從回傳 JSON 的 `resources[0].url` 取得最新網址。

### 宜蘭縣 ❌ 目前查不到 bulk 開放檔

宜蘭縣沒有像台北市那樣可整包下載的門牌坐標 CSV(data.gov.tw 上還躺著
[請各地方政府提供門牌座標檔的陳情](https://data.gov.tw/suggests/106384))。
所以**宜蘭 3 組的座標目前仍是概略值**(`approx: true`)。

可能的解法(都還沒做):
- **TGOS 全國門牌地址定位服務**(內政部,涵蓋全國 800 萬門牌):有 API,但**需註冊取得金鑰** →
  只能當「本機建置時」用,不可放進前端(違反本工具免 key 原則)。
  <https://www.tgos.tw/tgos/Web/Address/TGOS_Address.aspx>
- 逐點貼 Google Maps 網址(工具本身支援解析 `!3d!4d` 精確座標),人工但最準。

檔名要含 `yilan` 或 `宜蘭`,腳本才認得出縣市。

## 用法

```bash
cd map/scripts
node geocode-moi.mjs --validate   # 對照獨立來源(OSM)驗證換算是否正確,不改檔
node geocode-moi.mjs --report     # 列出每點能否定位、位移多少,不改檔
node geocode-moi.mjs --apply      # 寫回 builtin.json
```

`--apply` 對命中的點:更新 `lat`/`lng`、**移除 `approx`**、加上 `geo: "moi-address"` 標記來源。
沒命中的點**原樣不動、保留 `approx: true`** —— 寧可顯示「座標概略」,也不要假裝很準。

## 驗證結果(2026-08-01,台北市)

先拿 3 個「由 OSM/Nominatim 獨立查證過門牌」的點當標準答案:

| 點 | 門牌資料 vs OSM |
|---|---|
| 霞海城隍廟(迪化街一段61號) | 差 **6 m** |
| 迪化207博物館(迪化街一段207號) | 差 **3 m** |
| 永樂市場(迪化街一段21號) | 差 52 m |

3m / 6m 證明 **TWD97→WGS84 換算與比對邏輯正確**(若換算錯,三點會系統性地一起偏掉)。
永樂市場那 52m 是因為它是**整個街廓的大型建物**,OSM 標中心點、門牌標登記位置,屬正常差異。

**內部一致性**(更強的佐證):補正後同一條街的點會自己排成一直線 ——
大安路一段(南北向)5 點東西向只散 97m、南北 1174m;信義路四段(東西向)5 點南北只散 85m、東西 1139m;
永樂市場與大稻埕戲苑(同為迪化街一段21號)拿到**完全相同**的座標。隨機誤差做不出這種結果。

套用結果:**107 點中 62 點**改為門牌級。其餘 45 點維持 `approx`,原因分三類:
宜蘭 25 點(沒有資料來源)、地址查無此門牌 ~3 點(**地址本身可能就是錯的**)、
本來就沒門牌 17 點(夜市、步道、巷弄、水門)。

## ⚠ 這個方法修得了什麼、修不了什麼

- **修得了**:座標誤差。原本用街道推估可能偏 100–1000m(實測最大位移 1088m),補正後到門牌級。
- **修不了**:**地址本身寫錯**。錯地址會被精準地定位到錯的建築 —— 比概略座標更危險,
  因為 `approx` 警告會被拿掉。所以「查無門牌」的點要當成**地址有問題**去查,不要硬湊。

## 新資料建議做法(這次學到的)

1. 產生資料時,**地址一定要寫到門牌號**(`○○路○段○號`),巷弄也寫清楚 —— 有門牌才補得了座標。
2. 先跑 `--report` 看命中率;**查無門牌 = 地址存疑**,先修地址再說。
3. 確認後 `--apply`,再用 `--validate` 的方式抽樣對照獨立來源。
4. 座標沒把握就**誠實留 `approx: true`**,前端會顯示「座標概略」。
5. 前端外連 Google Maps 一律用**店名 + 地址**(見 `js/main.js` 的 `gmapQuery()`),
   不要用我們的座標 —— Google 自己的搜尋比我們準,且會落在店家資訊卡。
